# SWE-agent 文献调研报告

**调研文献：** Yang, J., et al. *SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering*. NeurIPS 2024。[论文原文](https://proceedings.neurips.cc/paper_files/paper/2024/hash/5a7c947568c1b1328ccc5230172e1e7c-Abstract-Conference.html)

## 一、研究问题与核心方法

真实代码仓库的缺陷修复需要理解问题、定位代码、修改文件并运行测试。SWE-agent 研究的是：在基础模型不变的情况下，能否通过改进模型操作计算机的接口，提高任务解决率？

论文提出智能体—计算机接口（Agent-Computer Interface，ACI），统一设计可用动作、工具说明、执行反馈与交互历史。系统在 Linux shell 上增加专用操作，形成“搜索定位—查看与编辑—执行测试—根据反馈修订—提交补丁”的流程。其关键设计包括：汇总搜索结果并提示缩小查询；通过带行号的文件窗口和指定行编辑减少操作步骤；编辑后立即回显内容，对部分语法及 lint 错误拒绝应用修改；压缩较早的观察，减少无关上下文。核心贡献是将交互接口作为影响智能体表现的设计变量。[原文第 2—3 节](https://arxiv.org/html/2405.15793v3#S2)

## 二、主要实验结果

论文主要使用 SWE-bench 评估仓库级缺陷修复，指标为补丁通过相应测试的任务比例（% Resolved）。采用 GPT-4 Turbo 时，SWE-agent 在全集 2,294 个任务中解决 286 个，解决率为 **12.47%**。同一模型在 Lite 子集的结果如下。

| 方法 | SWE-bench Lite 解决率（300 个任务） |
| --- | --- |
| SWE-agent | 18.00% |
| Shell-only：通过通用命令行交互 | 11.00% |
| RAG：根据检索到的文件直接生成补丁 | 2.67% |

消融实验进一步显示：将汇总搜索改为逐条查看，解决率由 18% 降至 12%；取消编辑中的 lint 检查后为 15%；使用完整交互历史替代保留最近五条观察时为 15%。这些结果支持搜索呈现、编辑反馈和上下文管理对任务表现的影响。另在短代码调试任务 HumanEvalFix 上，Python 的 pass@1 为 87.7%，该结果对应单文件调试能力。[原文表 1—3](https://arxiv.org/html/2405.15793v3#S4)

## 三、研究局限性

1. **适用范围受限。** 仓库级实验主要涉及 12 个 Python 仓库，使用的是论文当时的模型与预算配置，尚不能据此推断物理出题等教育任务的效果。
2. **性能提升的归因需区分比较对象。** 相比非交互式 RAG，SWE-agent 同时增加了多轮反馈与计算开销，差异不能全部归于某个接口组件；同模型的 Shell-only 比较与组件消融提供了更直接的依据。
3. **统计证据存在边界。** 附录报告了完整系统的多次运行，但未为各项消融差异提供配对置信区间或显著性检验，不能把特定配置下的分数差异视为普遍规律。
4. **测试通过不等于全面正确。** 测试无法穷尽维护性和未覆盖的回归，lint 检查也不能保证业务语义正确；失败分析依赖模型自动分类，存在标注误差。接口改善了操作条件，正确修复与错误恢复仍是难点。[原文实验与失败分析](https://arxiv.org/html/2405.15793v3#S5)

## 四、对 PhyQGen 项目的启发

PhyQGen 面向高中物理教师，计划通过命题、绘图、文本校验和图文校验智能体生成习题草稿，再由教师审核定稿。

**1. 将内部校验意见转化为可执行反馈。** 在已规划的问题位置、修订建议及对应版本基础上，补充明确的检查对象与判断依据。例如，题干描述物体向右运动而图中速度箭头向左时，反馈应指出具体冲突，并交给相关生成智能体修订。这些意见用于系统内部修订。

**2. 控制上下文，并保证反馈对应当前版本。** 优先提供当前题干、答案、实际图片、相关知识依据与未解决问题，避免反复传入全部历史草稿。生成阶段修改题设且影响图示时，应同步更新蓝图与配图，并重新校验，避免沿用旧版本的通过结论。

**3. 用有限修订和程序检查约束错误传播。** 沿用默认每题最多三轮（含首次生成）的约束，超时或校验输出无法解析时如实记录未完成，保留可用草稿。可探索用确定性程序检查数值代入与单位关系，物理模型适用条件和教学适配性仍需教师判断。教师收到草稿后直接审核、修改与确认，不再触发自动校验。以上边界与现有[功能规格说明书](../requirements/functional%2Bnonfunctional_spec.md)保持一致。

**4. 通过独立评价检验实际收益。** 在原定不少于 30 道样题及拟邀请 3—5 名教师反馈的计划基础上，建议增加同需求、同模型、同预算下的直接生成与结构化反馈修订对照，记录物理错误、图文一致性、教师初审可用率、审核修改时间及调用成本。初审可用指无需实质修改即可确认；教师评价应独立于生成与校验模型，重点检验系统是否减少真实审核负担。[项目验证计划](../requirements/problem_definition.md)与[试评验收标准](../requirements/functional%2Bnonfunctional_spec.md)
