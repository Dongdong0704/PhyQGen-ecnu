# PhyQGen 风险管理计划

## 1. 目标、范围与当前基线

风险管理旨在降低错误习题、图文错配、错误定稿、数据越权、外部调用失控和课程交付延误的可能性，同时抓住可验证的复用与提效机会。覆盖分析、设计、开发、测试、发布与试用维护，既关注单项风险，也关注整条“检索—生成—校验—人工确认—保存导出”链路的整体不确定性。

### 1.1 已知事实、假设和风险分开处理

| 类型 | 当前情况 | 管理处理 |
| --- | --- | --- |
| 已知事实 | 正式前后端和核心引擎目录仅有占位文件；架构文档为空 | 属于当前待完成工作，通过Issue #6等任务补齐，不直接写成“开发未完成风险” |
| 已知事实 | Vue前端原型存在，模型、检索、自动校验、连接测试和索引重建为本地模拟，使用localStorage | 可以验证交互；不能据此声称真实服务已接通、并发已实现或物理正确性已达标 |
| 已知事实 | 原型有优秀习题、评分和讨论等保留功能；部分原型说明引用仓库外旧项目或当前树内缺失的说明文档 | 先做资产与范围核对；由此引出的迁移返工或范围膨胀才是不确定风险 |
| 计划与约束 | 单次1～5道；默认最多3轮含首次生成；教师编辑和确认不重新调用智能体；TXT只导出已确认版本 | 列入契约、测试与发布门槛，不能随意降级 |
| 计划目标 | 拟邀请3～5名教师、使用不少于30道样题比较人工与系统辅助流程 | 招募和试评尚待实施，其未按时完成的可能性属于风险 |
| 待核验假设 | 四名公开Issue参与者的实际岗位、每周可投入时间、可用模型/配额、预算上限、正式技术栈和里程碑日期 | 首轮计划会登记；假设变化时重新评估相关风险，不能当成已获承诺 |

例如，“架构文档为空”是事实；“由于跨模块契约尚未固定，接口实现可能不一致，从而造成联调返工”才是风险。风险一旦发生，建立问题/缺陷Issue并执行应急措施，保留原风险记录以跟踪残余风险。

## 2. 管理方法与职责

### 2.1 管理闭环

1. **识别**：从需求FR/US/AC、原型差异、外部依赖和课标资料出发；在需求评审、接口评审、模型变更、教师试用、发布检查和复盘中新增风险。
2. **分析**：采用“原因—可能发生的事件—对范围/质量/工作量/进度/成本的影响”表述；给出概率P、影响I、评分、预警信号与责任人。
3. **规划应对**：威胁选择规避、减轻、转移或接受；机会选择开拓、提高、共享或接受。每项措施写出执行节点、成本和可验证的完成条件。
4. **实施**：将措施拆成有主责、备份、截止/检查点和验收条件的Issue或迭代任务；没有落实措施时不得降低评分。
5. **监督**：周会复查全部活动风险；一级风险每个工作日检查；触发时转为问题并升级。措施验证后重估残余P、I、优先权，必要时补充次生风险。

风险源采用课程维度：资源、项目管理、外部因素、技术、进度。物理质量、教学评价、安全和数据问题可作为技术或外部因素的子类，不另造与课程不兼容的分类体系。

### 2.2 角色责任与权限

| 角色 | 风险职责 |
| --- | --- |
| PM | 维护台账和风险议程；协调资源、排期与预算；组织升级；检查风险行动未因兼岗而遗漏 |
| REQ | 负责范围、物理和教学评价、教师资源、课标口径与材料使用边界 |
| FE | 负责展示、编辑、公式/图片、原型迁移和教师操作提示的相关措施 |
| BE | 负责接口、异步任务、权限、持久化、版本一致性及部署恢复 |
| AE | 负责模型、提示词、检索、配图、自动校验、轮次与调用资源 |
| QA | 独立设计异常/回归样例，核查风险应对证据，维护发布门槛和试评记录 |
| 全体组员 | 发现后及时报告，不因“目前没报错”而忽略不确定性；参加风险判断与措施复核 |

上述为岗位责任，具体账号映射和备份按沟通计划首次评审登记；每条风险表中的岗位必须落到一名主责。PM可在约定范围内调整任务顺序；改变必需功能、课程节点或质量门槛须经团队评审，必要时由PM请课程教师确认。风险评审不是把教学内容正确性的责任转交给模型或供应商。

## 3. 评估规则与优先权

### 3.1 概率P与影响I

概率区间用于统一主观判断，针对“从本次评估到下一相关交付节点”的发生可能性。没有调用和缺陷数据时只记判断依据，不将分数包装成统计预测；积累数据后再校准。

| P | 发生可能性区间 | 用法 |
| --- | --- | --- |
| 1 | ≤10% | 发生条件较少，目前证据弱 |
| 2 | >10%且≤30% | 有可解释的发生路径，但有一定控制 |
| 3 | >30%且≤50% | 条件部分具备，尚未验证控制有效性 |
| 4 | >50%且≤70% | 依赖较多或已有原型/需求差异，需优先验证 |
| 5 | >70% | 触发条件接近满足；仍须区分是否已成为事实 |

| I | 影响程度 | 进度参考及业务含义 |
| --- | --- | --- |
| 1 | 很低 | 局部修正，不影响关键验收，通常≤0.5个工作日 |
| 2 | 较低 | 单模块受限，通常>0.5且≤1个工作日 |
| 3 | 中等 | 需要局部返工或重测，通常>1且≤2个工作日 |
| 4 | 高 | 跨模块返工或主要功能受损，通常>2且≤5个工作日 |
| 5 | 很高 | 关键交付可能失效或延误>5个工作日；或涉及物理质量严重失守、错版定稿/导出、越权或数据不可恢复损失 |

进度天数只是参照；影响取质量、范围、进度、成本等维度的最大值，不能用工作量小掩盖严重质量或安全后果。风险评分 `S=P×I` 用于排序，不是期望损失金额。

### 3.2 工作量、进度和成本影响

为了与课程表格兼容，保留高/中/低描述。以下为本团队建议的初始分档，不是已发生损失；首次估算会据实际容量修订。

| 维度 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 额外工作量 | ≤1人日 | >1且≤3人日 | >3人日；1人日按8小时用于换算，投入可分散完成 |
| 关键路径进度 | ≤0.5工作日 | >0.5且≤2工作日 | >2工作日或影响课程检查节点 |
| 直接费用 | ≤阶段已批准预算的5% | >5%且≤15% | >15%或可能突破已批准上限 |

尚无金额基线时，成本高/中/低只表示相对暴露，登记为待测算，并先统计调用量与单位成本，不能据此推导金额承诺。对机会，工作量记录需要投入的工作，进度/成本描述潜在收益，不能与威胁损失直接抵消。

### 3.3 优先权及跟踪频率

| 优先权 | 判定 | 行动和跟踪 |
| --- | --- | --- |
| 一级（优先处理） | S≥15；或涉及定稿版本、越权、泄密等不可带入试用的门槛，即使S较低也提升 | 纳入当前迭代；每个工作日检查；触发后立即按沟通计划升级 |
| 二级（计划处理） | 8≤S≤14，且未触发门槛提升 | 纳入下一相关里程碑前的任务；每周至少1次及相关变更时检查 |
| 三级（持续观察） | S≤7，且未触发门槛提升 | 每周简查；迭代或阶段结束重估 |

距相关交付节点不足2个工作日且预警未解除，可临时升为一级。机会使用同一评分衡量关注度，但不拥有绕过安全或质量门槛的权限。

## 5. 预警、应对、责任与验证

## 6. 成本、时间储备与整体项目风险

### 6.1 储备与调用预算

- **时间储备**：建议在剩余开发、联调和验证可用工时中预留15%作为应急缓冲，首次估算会确认具体人时与所覆盖风险。缓冲按实际容量计算，不直接套用课程周数，不把同一人时重复算给多个风险。
- **费用基线**：在真实付费调用前，由PM与AE登记阶段预算上限B、账户/配额、单价来源、预期调用构成和剩余余额；未确定B时，费用分档保持待测算，不以主观风险分数替代预算。
- **小批测量**：先用少量单题分别测文本、图片、嵌入与多模态调用，再估算30道样题及回归的开销。教师编辑/确认应新增零次模型调用，单独监控。
- **使用规则**：消耗应急缓冲、改变并发或扩大样题实验前记录原因、关联风险、预计消耗和剩余量；超过原范围或预算必须重新评审，不能靠无限重试解决质量问题。

初步调用构成可按以下方式检查：

```text
总费用 = Σ（各服务实际计费调用/输入输出量 × 对应单价） + 已确定的存储/部署费用
单题调用 = 各轮命题 + 文本校验 + 按需绘图 + 按需图文校验
          + 适用的检索/嵌入 + 有限传输重试
```

仅作容量提醒：若5题都配图，3轮中每轮均调用四类智能体，便是60次智能体调用，尚未包含检索与传输重试。实际编排可跳过不需要重做的步骤，应以账本实测为准；此数不是已实现流程或费用预测。

### 6.2 以里程碑控制整体不确定性

课程大纲为分析1～2周、设计3～6周、开发7～10周、测试11～13周、发布14～17周。以下为适合本项目的建议检查点，不将当前日期强行映射为某一教学周；具体日期和负责人由实际课表、Issue和团队容量确定。

## 7. 质量门槛与试评口径

### 7.1 不得带入真实试用或候选发布的问题

1. 使用原型本地身份代替正式服务端认证授权，或存在真实密钥泄露、跨教师资源访问。
2. 未确认版本可作为定稿导出；修改后继承旧确认；确认保存失败仍显示成功；教师编辑/确认触发新智能体调用。
3. 要求配图却在图缺失、不可预览时允许不完整定稿；内部校验异常被默认判通过；无草稿保存成功仍显示任务完成。
4. 真实数据不可恢复丢失仍继续开放相关写入，或公开交付含已发现的未授权/未脱敏材料。

这些是功能和安全门槛。少量抽样中未发现物理错误不能证明模型永不出错，系统始终保留教师人工审核和明确确认责任。

### 7.2 质量与用时评价

按现有需求拟邀请3～5名教师，以不少于30道力学、电学等样题覆盖文本/配图、单题/批量及相应异常；先做小批试评，校准判据和记录方式，再由REQ、QA及团队固定正式评价阈值，必要时请课程教师确认。阈值固定后不能根据结果临时放宽。

| 指标 | 记录方法与风险用途 |
| --- | --- |
| 物理错误、答案解析及图文一致性 | 按题目和版本分类，记录严重性、依据和人工复核；重点验证R02/R03 |
| 教师初审可用率 | 无需实质修改即可确认的草稿数／全部受评草稿数；同时报告请求题数、成功保存数、失败数，防止只评价成功草稿掩盖失败 |
| 标签成立性 | 记录设问、所需活动和答案/评分点是否对应C1～C6；保留分歧及解决依据，不转换为学生能力分 |
| 时间 | 分别记录生成、自动校验、人工审核修改及从配置到确认总耗时；人工基线使用同一组命题要求 |
| 调用与费用 | 每服务调用数、重试、轮次、输入输出量与费用；比较同需求同预算的方案，不以增加无限调用换取表面质量 |
| 可复现性 | 关联提交、模型标识、可用版本信息、提示词、索引、参数及样题；供应商不暴露底层版本时明确写明限制 |

小样本结果用于项目验证和后续改进；报告保留失败、教师分歧及环境变化，不能据此声称已普遍提升学生高阶思维或保证任意高中知识点质量。

## 8. 风险监督、升级与关闭

### 8.1 例行监督

- 每次周会按ID检查：发生可能性是否变化、预警是否触发、措施是否落实、证据是否齐全、主责是否有时间执行；先看一级风险和临近里程碑的二级风险。
- 对R06/R07记录近期调用失败、超时、轮次和费用；R09/R10/R11检查回归门槛；R14检查招募及样题覆盖；R16检查真实端到端增量与剩余缓冲。
- 需求、接口、模型/提示词、索引、人员或部署环境变化时，不等待周会，立即复查受影响风险。
- 一项风险未触发不等于已关闭。只有触发窗口结束、控制经验证或暴露已消除，才可讨论关闭；仍有持续暴露的保留为监控中。

### 8.2 触发与升级

风险责任人发现触发后，在关联Issue记录时间、任务/题目/版本、现象、影响范围和证据，关联原风险ID，状态改为“已发生/问题处理中”。按沟通计划C08/C09/C13处理：普通阻塞超过1个工作日升级PM；继续影响课程节点时由PM请教师协调。泄露、越权、错版定稿/导出或数据损失立即止损，在约定协作窗口内目标2小时确认处理人，窗口外下一窗口立即响应。

需要对用户说明时，由REQ和PM给出“影响了什么、应暂停什么、怎样恢复/复核”的具体信息，不把内部自动校验意见直接公开为教师审核结论。外部模型工单只提供脱敏请求与错误信息。

### 8.3 状态、残余风险与关闭条件

建议状态流为：已识别 → 已评估 → 应对中 → 监控中 → 已关闭；任一活动状态可转为已发生，并关联问题单。问题修复后重新评估残余风险，可能回到监控中，而非直接删除。

每条更新记录以下字段：

```text
风险ID / 更新日期 / 对应里程碑：
当前状态 / 主责账号 / 备份账号：
初始P、I、S、优先权及判断依据：
本次预警和实际观测（分母、环境、版本）：
已执行措施 / 行动Issue与截止或检查点：
措施成本与缓冲消耗：
验证证据 / QA复核人：
残余P、I、S和优先权 / 变化理由：
次生风险 / 需升级事项：
下一复查日期 / 关闭条件及确认人：
```

PM与责任人提出降级或关闭，QA复核控制证据；涉及教学质量由REQ参与，涉及课程范围/节点的接受决定由全组评审并按需向课程教师说明。零缺陷、恢复成功和成本改善等结论均需证据。接受残余风险须记清适用范围、有效期和再次触发条件，不能接受违反已定发布门槛的问题。
